# 修回材料交接给写作 Agent

收到大修、小修或其他明确学术修回要求后，本 Skill 的目标是把材料整理成客户现有写作 Agent 能直接使用的本地文件夹，不自动调用另一个 Agent，不修改论文科学内容、不代写逐条回复、不运行新分析，也不自动上传或提交修回。客户之后把另一 Agent 完成且确认的材料交回，并要求投稿时，再使用[投稿执行](execution.md)。

## 每轮独立整理

在本篇原期刊记录下，为本次修回创建独立文件夹，保留原投稿及之前各轮不变。优先复用已保存的**实际提交版本**、决定信、编辑与各位审稿人的完整原文、期刊要求、图表及补充材料；从授权的系统或已启用邮箱补充可取得文件。无法确认是否为实际提交稿、缺少评论或附件、来源不可访问时清楚标注，不把本地最近修改稿冒称实际投稿稿。需要作者信息时沿用本次已确认的快照；准备交接不要求重新填写整个作者表。

为其他 Agent 提供一份简短入口说明：稿件标题与期刊、稿件号、修回轮次、期刊显示的截止日期及原文/精度、材料路径、实际来源和待补事项。将编辑意见和不同审稿人的意见按来源和顺序清楚分开，保留完整原文；需要概览可用不改变含义的简短整理，但不能遗漏子问题、编造审稿意见或写出仿佛已经完成的答复。

复制或引用客户授权的现有文件，确保写作 Agent 看得见；材料路径不能解析、格式工具缺失或文件不可取得时标明，不虚构打包成功。不默认复制含患者直接身份信息的原始数据；若后续分析需要数据，应由客户授权并先在本地形成去直接标识的工作文件。普通文件夹和 Markdown 即可，不要求固定写作产品、专用程序、JSON 或 ZIP。

交付入口说明与文件夹路径，清楚标注“供写作 Agent 处理，尚未修改或提交”。可附一句供客户复制的指令，要求其 Agent 根据原始意见和真实资料处理、标明缺失事实并保留原稿；不要把候选回复、虚构分析或自动调用外部写作 Agent 当成交付结果。需要客户提供的材料集中列出。
