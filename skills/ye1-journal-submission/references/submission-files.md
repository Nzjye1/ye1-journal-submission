# 文件上传、预览与正式提交

## 上传与核对

以本次确认和留档的文件为准，根据当前页面的角色选择主稿、匿名稿、标题页、图件、补充材料、投稿信和期刊要求的其他附件；先判断文件用途和版本，不凭相似文件名猜测。读取实际槽位及数量，确认文件顺序、必需标签和支持格式；不能确定时先做其他步骤并集中询问。

上传后等待系统处理，核对文件名、角色、数量、顺序及可用预览；必要且可用时下载比对内容。替换主稿可能覆盖系统已填写的标题、摘要、作者或声明，最终主要文件确定后再核对[表单](submission-fields.md)。双盲投稿检查系统预览、文件名、题页分离以及图表中可见的身份信息；无法检查的部分标记未知。

发现图稿需要修正时，按[图稿处理](formatting-declarations.md)优先查找源文件和自行处理；修改后另存并检查，重新上传仍按客户授权和当前页面要求执行。

## 最终预览与动作

系统生成合并审稿 PDF 时，查看其是否包括所需主稿和附件，检查页序、作者匿名、图表、表格、公式、字符和截断，并对照系统表单；可修正的问题修正后重看。预览若标明为样例、内容与本次文件不符或来源无法确认，不当作当前稿件的最终预览；记录差异并查找实际生成文件。若没有生成预览或无法访问，记录已核对和无法核对的项目，不声称全部检查完成。

识别当前页面动作的实际后果，不仅凭按钮是否写着 Submit 判断：页面里的 Submit 可能只是保存分类，而部分系统的 Approve Submission 才是正式投稿。客户要求停在提交前就停在该系统最后的对外提交动作之前；客户已明确授权提交且宿主允许时，在材料和必要决定完成后继续，不重复索要同一授权。

## 结果和留档

提交后核对同一账号、期刊及稿件的确认页、稿件号或已提交状态；留存实际可见的证据。若结果未知先只读回查，不再次点击；没有确认凭据时保持未知。将实际上传文件、可核实的作者/表单和状态、稿件入口与确认材料记入本次[本地版本](submission-snapshots.md)。系统生成文件可能被转换；只有能下载或核对时才声称与本地版本一致。草稿、文件已上传、正式提交和期刊接受是不同状态。
