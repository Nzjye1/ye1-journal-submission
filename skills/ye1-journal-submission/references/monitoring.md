# 投稿状态监控

使用宿主浏览器或电脑操控，只读查看投稿系统并比较变化。不限期刊或出版社，
无需邮箱或专用适配；由 Agent 理解当前页面。已有投稿可直接接入。
客户明确选择并授权接收投稿邮件时，另读[可选邮件接收](mail-optional.md)；未开启时不访问邮箱。
客户希望汇总多篇文章或已有总览时，先读[多篇文章管理](management.md)，逐篇关联对应投稿记录，并将每次可核实的结果更新到总览。
接入账号、读取审稿详情或编辑决定时读[进展与下一步](monitoring-details.md)；安排监控、提醒或查看运行状态时读[监控安排](monitoring-schedule.md)。

## 查询与记录

复用详情页、投稿回执、账号会话和已有记录，核对当前账号、期刊、标题及稿件编号。
按平台和账号组织多篇查询，集中处理确需客户接手的登录，其他能查询的稿件继续；已有资料无需客户重新逐篇填写。
多标签页可能共享登录身份；出现登录页、Not Found 或权限错误时先核对账号并尝试合理
恢复，不能直接解释成拒稿或稿件删除。确需用户验证时按[交互指引](execution.md)接手。

读取状态原文及可见的进度历史、轮次、截止日期，保存真实查询时间和稳定来源。
平台更新日期与本次查询时间分开；页面没给出的决定、人数或完成率不要推断。
“邀请审稿人”“接受邀请”“收到报告”分别记录，处理中不代表接受或拒稿。
按[进展与下一步](monitoring-details.md)记录页面实际给出的审稿人数量、决定信、待办和截止日期；首次观察时间不冒称状态实际发生时间。能只读获取的系统内文件存入本篇私人目录，不能获取则说明缺口。

首次成功查询建立基线；以后与上次可信读数比较。关注状态、新事件和截止日期，
排除焦点、菜单或文字空白变化。失败保留最后可信状态；本次没读到的字段保留原时间，
不当作已清空或已更新。多篇稿件逐篇记录结果，一篇失败不妨碍其他稿件。
有总览时同时显示最近一次查询的结果与时间；查询失败须显示原因或需接手，并保留上次可信状态及最后成功查询时间，从未成功则标为未知。多账号分别核对，避免把一篇稿件的状态写到另一篇；改投后按当前记录核对期刊与稿件号，不沿用原刊状态。记录每次实际观察及来源，不补造漏查历史。
普通笔记或表格即可，保留足够历史供下次比较；不要保存密码、验证码或带登录令牌的链接。

## 通知

- 首次接入或用户主动查询：正常报告当前状态。
- 定时巡检无变化且正常：安静保存记录；有实质变化或需要客户处理时通知。
- 首次或性质改变的访问故障：说明问题和所需动作，相同未解决故障不每天重复催促。
- 报告平台原文及发现时间；没有正式决定证据时，不把推测说成正式接受。
- 提醒尽量说明文章、期刊、变化或故障、可见截止、下一步及实际查询时间；按[监控安排](monitoring-schedule.md)处理截止提醒和久未变化，使用客户已选且有权限的渠道。

查询不会自动延伸到回复、修回、上传或提交。按客户已有通知偏好执行。

## 每日巡检

用户要求定时监控时，使用宿主自带调度工具创建或更新任务，先查是否已有同用途任务，
避免重复。绑定本 Skill、私人记录位置、稿件和时区；未指定时间可说明默认当地 09:00，
时区不明则询问。可使用以下任务提示词：

> 读取指定私人记录中的稿件，使用 ye1-journal-submission 的监控指引，用浏览器或电脑操控
> 逐篇核对账号和稿件，只读查看状态及进度，与上次可信记录比较，保存各篇历史并更新已有总览。仅在实质变化、
> 新故障、到期提醒或需要客户处理时按监控安排通知；无变化时安静记录。仅在客户明确启用指定邮箱且要求定时接收时按可选邮件指引查询，否则不访问邮箱；不发信、填写、上传或提交。
> 无法访问时保留旧状态，不补造漏查历史。

创建后核对任务启用状态和时间；任务创建、一次查询成功、定时实际运行是不同结果，
按已有证据报告。执行环境需要能访问记录、浏览器和会话，不能默认关机或休眠时仍可运行。
按[监控安排](monitoring-schedule.md)区分任务启用、每篇纳入情况、最近实际尝试、最后成功查询和可核实的下次计划，不凭计划时间冒称实际执行。
无调度能力时交付提示词并说明未启用，不改造为独立服务。任务重叠时避免重复操作和通知。

用户要求改时间、增减稿件、暂停或停止时，更新对应宿主任务及查询对象，并核对生效；
保留已有历史，不只口头答应。稿件接受、拒稿或撤回后，按用户已有约定调整或结束该稿巡检；
客户已要求录用后继续跟进且宿主可用时，可按授权跟进可见的校样和出版事项；未约定时在报告结果时一次询问是否继续，不默认每天重复通知终态。
