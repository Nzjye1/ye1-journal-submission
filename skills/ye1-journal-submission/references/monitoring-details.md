# 投稿进展、决定和下一步

## 接入与多账号

按客户指定的文章和授权范围，复用本地总览、稿件记录、投稿回执或已登录系统的可见列表，整理期刊、稿件标识、入口和账号，不要求客户逐篇重复填表。只询问实际无法从现有材料或页面确认、又妨碍本次查询的入口或身份。没有获得可访问入口的文章标为待接入，不能声称已覆盖全部稿件。

按平台和账号组织可独立完成的查询，尽量复用已授权的可用会话；多个标签可能共享账号，不能假设标签相互隔离。每篇都核对当前账号、期刊及稿件身份，信息不足以区分时标记待核对，不把读数归到猜测的文章。登录过期或验证需要客户接手时，集中列出相应账号及需要完成的动作，其他能查的文章先继续；处理后从原稿件位置复核身份并继续。不要索取或记录密码、验证码或会话令牌，不绕过验证和网站限制。

## 可见审稿进展

在当前稿件可见页面读取状态原文、期刊展示的历史和轮次；若系统公开对应信息，可分别记录已邀请、接受邀请和已返回报告的审稿人数或事件，注明页面原文、来源及查询时间。系统没显示的项目标为未知，不根据其他数字推算缺失人数、应邀总数或完成率；“邀请”“接受邀请”“收到报告”不是同一事件，也不代表接收论文。

对客户可用简短中文解释状态及可见变化，但不同系统的状态含义可能不同；不把推测写成期刊决定。时间线保留平台实际给出的事件日期及其精度，并与 Agent 观察时间分开。平台没有发生日期时，只能说“首次观察到该状态的时间”或“自该次观察以来仍看到此状态”，不能断言状态从那天开始或期间没有经历其他变化。查询间隙可能发生未显示或未捕获的变化，不补造历史。

## 编辑决定与待处理事项

页面出现修回、拒稿、接收或其他决定时，在授权及页面权限内只读查看该稿件系统内可访问的决定信、编辑意见、审稿意见、相关附件及日期；能保存时放入该稿对应的私人投稿/修回文件夹，保留来源。若只能看到状态、不能获取判断所需的决定信、意见或附件，记录所见并主动向客户说明缺口，请其提供必要材料；具体按[投稿后处理](post-decision.md)衔接。客户明确启用并授权时也可按[可选邮件接收](mail-optional.md)查找相关邮件。系统状态、编辑决定和已经完成的行动分别记录；没有明确证据时不声称正式接收、已修回或已改投。

从实际决定和用户提供的材料中整理需处理事项、可核实的截止日期与原始表述；只显示日期时不编造具体时间或期刊时区。来源之间存在冲突时保留各自出处并标明待核对。可告知客户下一步是什么；客户要求或已有约定继续时，按[投稿后处理](post-decision.md)区分退回、修回交接、拒稿改投和录用后的校样或出版事项。只读监控不自行修改稿件、联系期刊、上传、签署或提交。查询不到具体意见时明确指出，不把通用建议当作该期刊的实际要求。

## 停留时间与期刊参考

投稿至今可从有来源的实际投稿日期计算；当前状态持续时间只有期刊给出确切进入时间时才能这样称呼。否则只计算自首次观察以来的时间并注明口径。期刊审稿周期只有在来源、年份、文章类型和阶段口径可比时才用作参考；例如首次决定时间不能直接当作当前审稿状态的限时。参考值不保证该稿件的决定时间，超过参考值也不等于出问题；客户需要时可准备问询草稿，但不自动发送。

将有来源的结果写入对应投稿记录，更新已有[多篇总览](management.md)；定时提醒和运行状态按[监控安排](monitoring-schedule.md)处理。报告文章、期刊、状态原文、实际变化、可见截止和待办、上次成功查询时间及缺口；未查到的内容保持未知。
