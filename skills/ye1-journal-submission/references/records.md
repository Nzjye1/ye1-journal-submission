# 轻量记录与交接

沿用客户的私人工作目录和现有记录方式，普通文件夹、Markdown 或表格都可以。
格式由 Agent 自行选择，不要求专用程序、JSON 表单、状态机或统一编号。
当前目录是公开 Skill 时另找合适的私人位置；确实无法确定位置再问客户。
客户希望统一管理多篇文章或已有总览时，按[多篇文章管理](management.md)关联各篇与各次投稿；单篇任务无需强制建立总览。

只保留下次继续需要的信息：

| 流程 | 需要记住的内容 |
| --- | --- |
| 准备 | 本篇选刊候选记录与客户选择、目标期刊与指南来源、稿件版本和文件位置、可复用作者档案位置与本篇确认快照、图稿来源及修改说明、已完成检查、待补事实及材料 |
| 执行 | 账号标识、草稿入口/编号、已填内容及上传版本、客户已作决定、推荐审稿人确认情况、当前停止位置和剩余事项 |
| 监控 | 账号与稿件身份、详情页、实际查询时间、状态原文与可见进展、决定与截止来源、变化历史、查询故障、定时任务运行证据和已提醒情况 |
| 可选邮件 | 客户已同意的邮箱和用途、实际查询范围、成功查询位置及相关消息标识、稿件归属和待核对事项；按需保留 |
| 投稿后 | 决定原文及来源、退回补正或修回交接包位置、拒稿及转投核查依据、录用后校样和出版事项、客户选择和真实后续结果 |

每次新投稿或改投建立本地独立版本文件夹；修回单独留存当前轮次。准备阶段保存稿件和确认信息，
实际投稿时保存实际上传文件、必要表单快照和真实结果，具体见[逐次投稿留档](submission-snapshots.md)。
保留原稿和已有历史，不无意覆盖。待补文件明确标识；下载校验等确有需要时再计算哈希，
不得编造校验值。操作结果不明就记为未知，继续前先查看平台，避免重复建稿或提交。

## 给客户的完成情况与待办

在一次任务交付或需要客户接手时，用当前可见的简短回复说明：本篇和当前真实状态、已经完成的结果及位置；仍需 Agent 处理的具体事项及能否继续；确需客户确认、提供或操作的事项及原因。没有的类别不用凑。优先在本次目标和授权范围内自行处理，不能完成时说明已尝试、阻碍和可行的下一步，不把已停下的工作说成正在自动进行，也不把等待期刊提供材料写成客户已逾期。

有多项待办时，区分阻碍本次目标或实际投稿的事项与可在后续阶段处理的事项；依据真实期刊要求和当前阶段判断，无法判断就标待核对。尽量合并提问、复用已确认答案，只让客户处理无法自行取得的事实或决定。将同样的简短待办写入或更新本篇私人说明，并保留截止日期、来源、相关文件路径和已完成情况；没有本地写入能力时说明。定时只读监控无变化且无新待办时仍按约定保持静默。

不要保存密码、验证码或登录会话。公开分发只包含通用指引，私人材料和截图始终留在
客户目录。交付时用普通语言说明结果，不要求客户理解内部字段或填写机器记录。
