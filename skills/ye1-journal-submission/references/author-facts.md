# 作者档案与稿件事实

## 一次建立，多次确认使用

客户可提供现有文件，也可回答集中整理的问题。先查看客户提供的稿件、作者信息文件、已有投稿记录及已知私人投稿管理目录，提取能识别的作者信息；不要让客户重新抄写已经提供的内容，也不要搜索无关目录。沿用现有可编辑作者档案，尚无档案时主动建立一份，而不是只在对话或单篇稿件中确认后就结束。

档案放在客户指定的私人投稿管理目录或已有多篇总览旁；未指定时，在宿主可用的用户私人文档目录建立稳定的 `投稿管理/作者信息档案.md`，不要放在公开 Skill 或仅本次会话可访问的临时目录。若既有档案采用 Word 等其他可编辑格式，可继续沿用，不强制迁移。无可访问的持久目录时说明档案尚未保存，请客户提供可写位置，并先完成其他工作。客户明确要求不保存时遵从其要求。

按人员整理可复用的信息：中文/英文姓名（明确姓和名）、邮箱、ORCID、中文/英文单位、单位和通讯地址等；只记录材料中已有或客户提供的事实，不适用或未知就留空，不根据中文姓名猜英文拼写。标明信息来源及已确认或待确认状态；同名人员或不同客户无法确定为同一人时不要合并。缺少非本次必需项不阻塞其他工作。

建立时集中展示从资料中整理的本次作者信息，顺带收集当前投稿确需且缺失的字段；客户本次已明确确认的内容直接记录，不重复询问。确认后把已确认的可复用信息实际写入或更新档案，记下档案位置，并在交付时告诉客户；无法写入时如实说明，不把“已在聊天确认”说成“已建立档案”。在本篇私人记录中保留档案路径及本次确认快照，方便新会话或其他 Agent 查找，不将整份跨稿件作者档案当作投稿附件上传。

**每次开始使用作者档案时**，包括新投稿、改投或作者信息发生变化时，展示本次拟用的作者、顺序、单位、通讯作者及本次已有的其他关键字段，请客户确认或提出修改。客户在当前任务中已明确确认同一内容时直接采用；无确认时只展示信息供确认，不把档案内容写入稿件、标题页或投稿表单，先做不依赖作者身份的工作。同一次投稿准备与执行之间如信息未变，复用已确认决定，无需每个文件重复询问。

## 同一作者，逐篇确认

作者档案中个人姓名、邮箱和单位可复用；每篇文章另记本篇实际作者名单、顺序、各作者所属单位、通讯作者、共同第一/通讯作者及贡献。可在同一份文档内分区，也可随文章材料保存；不强迫客户管理多份文件。新文章可以调用同一作者的已有资料，但必须确认该篇作者和单位对应关系；不同稿件、期刊和时间点的署名与机构可能不同，不能把其他论文的署名或贡献自动套用本篇。

客户提供了作者或单位修改时，按确认内容更新本篇文件；明确属于长期个人信息的修改同步更新共用档案，仅属本篇的作者顺序、贡献或单位变动只改本篇记录。性质不明时先保留共用档案，不擅自覆盖。历史投稿文件夹保留原来的快照，不因档案更新而自动更改。已经提交的稿件若变更作者，先核对当前期刊规则及必要的作者确认；不要假定系统允许直接修改。

## 文章专属事实

伦理审查/豁免、知情同意、登记、资助、利益冲突、数据可用性、作者贡献、发表同意和其他声明事实属于具体研究或稿件。先从当前稿件和用户提供的资料、对话及本篇已确认记录中查找；可以记录来源和确认情况以便同一篇稿件改投复用。不要把其他文章的伦理、无资助、无利益冲突、作者同意等视为本篇事实；不要根据“公开数据库”自动推断伦理豁免或知情同意情况。

本篇稿件或客户资料已清楚写明且彼此一致的事实，例如数据库名称和已说明的访问方式，可按原意直接用于声明草稿并注明来源，不为文字整理再逐项要求客户确认；这不等于独立验证了事实。资料标记未确认、相互冲突或需要作者作出额外承诺时，才针对该项询问。

资料冲突、确需作者作出承诺或本篇必要事实缺失时，集中询问客户；已确认事实不反复问。需要人工确认的内容不写成已确认事实。档案和记录不保存密码、验证码或会话令牌，不写回公开 Skill。
